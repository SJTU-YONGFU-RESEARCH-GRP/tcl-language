# 第 1 周 — 电脑会说话：`puts` 与脚本文件

> 本课对应总计划：[10 周 Tcl 学习计划](../../PLAN.md)。  
> 本周目标：让电脑按你的话打印文字；知道什么是 `.tcl` 文件。

---

## 学习目标

学完这一周，你应该能够：

1. 打开终端，用 `tclsh` 启动 Tcl。
2. 用 `puts` 把一行或多行文字打印到屏幕上。
3. 新建 `.tcl` 脚本文件，把 Tcl 命令写进去，再用 `tclsh` 运行整个文件。
4. 写 `#` 注释，说明重要代码在做什么。
5. 独立完成一张自我介绍卡脚本（可参考 `10_self_intro_card.tcl`）。

当你不用逐字抄写也能做到以上五点时，第 1 周就过关了。

## 大想法（用生活比喻）

电脑像一个听话的机器人：你写什么，它就做什么——不多也不少。你让它打印三行，它就打印三行；如果你少写了一个引号，它可能会停下来报错，而不会替你猜意思。

| Tcl 概念 | 生活比喻 | 本周你会用它做什么 |
|----------|----------|--------------------|
| 脚本 `.tcl` | 给机器人的一张「任务清单」 | 把命令存进文件，以后还能再跑 |
| `puts` | 「请把这句话说出来」（打印到屏幕） | 让屏幕显示你的话 |
| `#` 注释 | 给自己看的小纸条，电脑会忽略 | 给自己留提醒 |
| `tclsh my.tcl` | 「机器人，请按这张清单做事」 | 一条命令跑完整份文件 |

### Tcl 读代码的三步心智模型（心智核心）

无论代码多长，Tcl 解释器每次执行一行代码都遵循严格的三步循环：

```text
第一步：参数切分与分组 (Argument Grouping)
   按空格拆分单词；遇到双引号 "" 或大括号 {} 时，把包裹的整体视为单个参数。
      ↓
第二步：符号替换 (Value Substitution)
   如果参数被双引号包裹，计算里面的 $变量、[命令] 和 \转义符。
      ↓
第三步：命令调用 (Command Invocation)
   在命令表中查找第一个单词（如 puts），并把替换后的参数传给它执行。
```

本周还不需要复杂变量与循环。这一周只练「说话」：打印文字、理解参数分组、保存脚本、写注释。

## 开始前需要准备什么

### 工具

1. 电脑上的终端（命令行）。
2. 已安装 Tcl，并且能找到程序 `tclsh`。
3. 用来新建 `.tcl` 文件的文本编辑器（纯文本即可：VS Code / Cursor、nano、Notepad++ 等）。

### 检查 Tcl 是否可用

在终端输入：

```bash
tclsh
```

如果安装正确，通常会出现类似 `%` 的提示符（外观可能不同）。这说明你已经在 **Tcl 交互环境**里，可以输入 Tcl 命令了。

在 `tclsh` 里输入下面这一行并按回车：

```tcl
puts "Hello, I am learning Tcl!"
```

你应该看到：

```text
Hello, I am learning Tcl!
```

然后离开 Tcl：

```tcl
exit
```

这时你回到了普通终端。

### 一次运行整个脚本文件

你不必一直停在 `tclsh` 里。在项目根目录（`tcl-language`）下可以运行：

```bash
tclsh lessons/1/01_hello.tcl
```

意思是：「启动 Tcl，把这个文件从上到下读完并执行，然后结束。」

如果已经进入本课文件夹：

```bash
cd lessons/1
tclsh 01_hello.tcl
```

两种方式都对。练习时固定一种习惯即可。

## 概念 1 — `puts` 就是「把字打印出来」

`puts` 可以记成 **put string**：把一段文字放到屏幕上（通常打印完还会换到下一行）。

### 一条 `puts` 命令长什么样

```tcl
puts "你好"
```

拆开来看：

| 部分 | 例子 | 含义 |
|------|------|------|
| 命令名 | `puts` | 动作：打印 |
| 空格 | （一个空格） | 把命令和参数分开 |
| 参数（文字） | `"你好"` | 要打印的内容 |

### 本周要记住的规则

1. 先写 `puts`，空一格，再写文字。
2. 文字里有空格时，用英文双引号 `"..."` 包起来。
3. 普通的 `puts` 通常打印 **一行**，然后换行。
4. 拼写要准确：`Puts`、`PUTS`、`put` 在 Tcl 里都不等于 `puts`。

### 你输入的内容 vs 屏幕输出

如果你运行：

```tcl
puts "Hello, I am learning Tcl!"
puts "我的名字是小明。"
puts "我喜欢的颜色是蓝色。"
```

屏幕上应该正好出现三行：

```text
Hello, I am learning Tcl!
我的名字是小明。
我喜欢的颜色是蓝色。
```

注意：输出里 **不会** 出现 `puts` 这两个词，也不会出现引号；只有引号里的文字会被打印。

### 先不建文件，在交互里练

1. 启动 `tclsh`。
2. 输入一行 `puts`，回车，看输出。
3. 再输入第二行 `puts`，再检查。
4. 练完后输入 `exit`。

觉得顺手之后，再进入概念 2，把同样的想法存进文件。

## 概念 2 — `.tcl` 文件就是脚本（完整操作步骤）

在 `tclsh` 里临时打字适合做小实验。真正的练习要把命令存成 **脚本**：一个以 `.tcl` 结尾的纯文本文件，里面写满 Tcl 命令。

### 为什么要学脚本

| 交互式 `tclsh` | 脚本文件 `.tcl` |
|----------------|-----------------|
| 一次敲一行 | 一次写好多行 |
| 容易忘自己敲过什么 | 明天打开文件还能看见全部内容 |
| 适合 10 秒试一下 | 适合作业、作品，以及以后用 Calibre |

### 分步完成：创建并运行你的第一份完整脚本

第一次请按步骤慢慢做；熟练以后可以加快。

#### 步骤 1 — 选好工作目录

可以在项目根目录，也可以在 `lessons/1`。例如（项目根目录）：

```bash
cd /path/to/tcl-language
```

（换成你自己的真实路径。在这台机器上，项目常见路径是 `/home/yongfu/proj/tcl-language`。）

#### 步骤 2 — 新建文件

新建一个纯文本文件，命名为 `my_first.tcl`。  
可以放在 `lessons/1/` 里和其他例题放一起，也可以放在你自己的练习文件夹。重要的是：运行 `tclsh` 时你要知道文件路径。

#### 步骤 3 — 写入一份完整的第一份脚本

打开 `my_first.tcl`，输入下面这份 **完整** 脚本（不要只写两三行就停）。每一段都有作用：

```tcl
# my_first.tcl
# 第 1 周 — 我的第一份完整 Tcl 脚本
# 在项目根目录运行：
#   tclsh lessons/1/my_first.tcl
# 如果当前目录就是本文件所在目录：
#   tclsh my_first.tcl

# ----- 页眉：说明这是什么 -----
puts "================================"
puts "   我的第一份 Tcl 脚本"
puts "================================"

# ----- 正文：关于我的信息（请改成你自己的！） -----
puts "Hello, I am learning Tcl!"
puts "我的名字是小明。"
puts "我今年 10 岁。"
puts "我喜欢的颜色是蓝色。"
puts "今天我学会了 puts 和 .tcl 文件。"

# ----- 页脚：表示脚本跑完了 -----
puts "================================"
puts "脚本结束。做得好！"
```

每一部分在做什么：

1. **顶部注释** — 告诉人：文件名、属于第几周、怎么运行。Tcl 会忽略这些行。
2. **页眉 `puts`** — 打印清楚的标题边框，让输出好看、好读。
3. **正文 `puts`** — 真正的内容（你的信息）。请把名字、年龄、颜色改成你自己的。
4. **页脚 `puts`** — 标记结束，让你知道脚本已经完整跑完。

#### 步骤 4 — 保存文件

保存为纯文本，扩展名必须是 `.tcl`。不要存成 Word 或富文本格式。

#### 步骤 5 — 运行

在路径正确的目录下执行：

```bash
tclsh my_first.tcl
```

如果文件在 `lessons/1`，而你在项目根目录：

```bash
tclsh lessons/1/my_first.tcl
```

#### 步骤 6 — 对照输出

你应该看到：标题边框、若干事实行、结束边框。如果缺了内容，重新打开文件检查：

- 每一行 `puts` 的引号是否成对？
- 运行前是否已经保存？
- 运行的是不是你刚编辑的那份文件（路径对不对）？

#### 步骤 7 — 修改后再运行

只改一行（例如喜欢的颜色），保存，再运行一次 `tclsh`。看到新输出，就证明脚本是由 **你** 控制的。

### Tcl 怎样读脚本

Tcl 会 **从第一行读到最后一行**：

1. 如果是空行 → 跳过（没事做）。
2. 如果是 `#` 开头的注释（或行内 `#` 后面的说明） → 忽略注释文字。
3. 如果是 `puts "..."` 这类命令 → 执行它。
4. 然后读下一行，直到文件结束。

文件里面没有「开始按钮」。开始按钮就是终端里的 `tclsh 你的文件.tcl`。

## 概念 3 — `#` 注释是写给自己的

一行里 `#` 后面的内容是 **注释**。Tcl 既不会打印它，也不会把它当成命令执行。

### 整行注释

```tcl
# 这一整行只给人看
puts "电脑还是会打印这一句"
```

### 行尾注释

也可以在命令后面加一小段说明。Tcl 里可以用分号 `;` 分隔同一行里的内容；常见写法是：

```tcl
puts "电脑还是会打印这一句"   ;# 这句注释解释上面的 puts
```

第 1 周只要会在每一段前面写整行注释就够了。

### 怎样算好注释

好的注释回答：*这部分在做什么？为什么要写在这里？*

| 更好的注释 | 较弱的注释 | 原因 |
|------------|------------|------|
| `# 打印我喜欢的颜色` | `# puts` | 说明目的，而不是只重复命令名 |
| `# 自我介绍卡的标题边框` | `# 第一行` | 说明这一段的角色 |
| `# 把这一行改成你的真名` | `# 文字` | 告诉下一个修改的人该做什么 |

### 用注释暂时关掉一行

如果在 `puts` 前面加上 `#`，这行就 **不会** 执行：

```tcl
# puts "这一行不会出现在屏幕上"
puts "这一行会出现在屏幕上"
```

想暂时禁用某行、又不想删掉时，这个办法很有用。

## 概念 4 — 引号、空格和特殊字符（第 1 周详解）

### 双引号 `"..."`

本周几乎所有文字都建议用双引号：

```tcl
puts "Hello world"
puts "姓名：小明"
```

引号告诉 Tcl：「这一整段是一个参数」，即使中间有空格也没关系。

### 不带引号的单个单词

没有空格的一个单词可以这样写：

```tcl
puts Hello
```

它会打印 `Hello`。但初学者仍建议养成加引号的习惯：`puts "Hello"`。

### 为什么引号必须成对

每个开头的 `"` 都需要一个结尾的 `"`。

| 你写的内容 | 问题 |
|------------|------|
| `puts "Hello` | 缺少结束引号 → 报错 |
| `puts Hello"` | 多了一个引号 → 报错 |
| `puts "她说 "你好""` | 中间的引号会把 Tcl 搞糊涂（进阶话题，本周先避开） |

第 1 周请保持字符串简单：整句话外面只有一对引号。

### 方括号 `[...]` 在 Tcl 里有特殊含义

在 Tcl 里，`[something]` 表示「先把 `something` 当命令跑一遍，再用它的结果」。所以如果你只是想打印复选框，下面这样会出问题：

```tcl
puts "[ ] 还没完成"   ;# Tcl 会尝试执行名叫空格的命令——这不是我们想要的
```

第 1 周若要原样打印方括号，请用花括号（花括号会关闭这种替换）：

```tcl
puts {[ ] 还没完成}
```

完整可运行例子见 `12_run_checklist.tcl`。

### 花括号 `{...}` — 本周只需知道这一点

你现在 **不必** 完全掌握花括号。只有在必须打印 Tcl 会特殊处理的字符（例如 `[` 和 `]`）时才需要。第 2 周及以后会结合变量再系统讲解花括号。

## 常见错误（和解决办法）

| 现象 | 常见原因 | 怎么办 |
|------|----------|--------|
| `command not found: tclsh` | 没装 Tcl，或终端找不到它 | 请大人帮忙安装 Tcl；关掉终端再开；重试 `tclsh` |
| `extra characters after close-quote` | 引号少了、多了，或不成对 | 数一数 `"`；每段文字只保留一对匹配的引号 |
| `invalid command name "..."` | 命令词拼错，或某一行写坏了 | 确认命令正好是 `puts` |
| 好像什么都没发生 | 进了 `tclsh` 但还没输入命令 | 输入一行 `puts "..."`，或从终端直接运行 `.tcl` 文件 |
| 中文显示乱码 | 终端不是 UTF-8 | 把终端改成 UTF-8；或先用简单英文练习 |
| 脚本好像“没更新” | 改的是 A 文件，运行的是 B 文件，或忘了保存 | 先保存；确认传给 `tclsh` 的路径就是你刚改的文件 |
| `puts` 里的 `[ ]` 不见了或报错 | Tcl 把 `[...]` 当成「执行命令」 | 用花括号打印：`puts {[ ] 项目}`（见 `12_run_checklist.tcl`） |
